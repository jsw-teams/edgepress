EdgePress 对 **pages（页面）** 和 **posts（文章）** 采用不同的编辑方式。页面在 Markdown 前置资料中配置有序、可编辑的元素块；文章则使用 Markdown 渲染器。本文本身就是一篇实际渲染的文章，可作为语法参考。

文章渲染器使用 CommonMark 与 GitHub Flavored Markdown（GFM），随后会清理生成的 HTML。块级内容之间留一个空行；行内语法可以组合在段落、列表、引用和表格单元格中。

## 标题与段落

Markdown 有六级标题。文章页面的 `<h1>` 已由前置资料中的标题生成；正文使用 `##` 到 `######`，让页面始终只有一个明确的 `<h1>`。

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

CommonMark 还支持 Setext 标题：在标题下一行写 `=` 可以生成一级标题，写 `-` 可以生成二级标题。如果文章标题已经生成 `<h1>`，请只在正文使用二级形式；一级写法留在代码示例中。

```markdown
一级 Setext 标题
=================

二级 Setext 标题
-----------------
```

-------------------

下面实际使用其余标题级别，便于确认它们会变成 HTML 标题元素。

### 三级标题示例

#### 四级标题示例

##### 五级标题示例

###### 六级标题示例

普通文字组成段落。空一行就会开始新段落。段落中的单个换行通常会折叠成空格。要强制换行，在 Markdown 源文件的行尾加两个空格，再从下一行继续：

这一行用 Markdown 硬换行结束。  
这句话会显示在下一行。

单独一行写三个连字符、星号或下划线可以生成分隔线：

---

星号分隔线：

* * *

下划线分隔线：

___

## 强调、代码与字符

用 `*斜体*` 或 `_斜体_` 表示 *强调*；用 `**粗体**` 或 `__粗体__` 表示 **加重强调**。也可以组合为 `***粗斜体***`，并用 `~~删除线~~` 表示 ~~删除文字~~。

反引号用于 `行内代码`。多行代码用三个反引号包起来，也可以标注语言，供代码样式使用：

```js
const site = { renderer: 'EdgePress', markdown: true };
console.log(`Building with ${site.renderer}`);
```

也可以使用波浪号围住代码：

~~~text
这个围栏代码块使用波浪号。
~~~

CommonMark 也支持每行缩进四个空格的代码块：

    const indented = '前面有四个空格';

要显示反引号本身，可用两个反引号包住单个反引号：`` ` ``。反斜线可以转义 Markdown 标点，例如 `\*这不是斜体\*`；字符实体 `&lt;` 和 `&amp;` 会分别显示为 `<` 和 `&`。

## 链接与图片

行内链接写作 `[快速入门](/quick-start/)`。也可以把目标地址集中写在文末，例如[构建指南][build-guide]。GFM 会自动识别 https://www.markdownguide.org/ 这样的裸网址、<https://commonmark.org> 这样的尖括号网址、www.example.com 和 team@example.com 这样的邮箱。链接文字应当说明目标内容。

[build-guide]: /quick-start/

图片与链接格式相同，只需在前面加感叹号，并提供有意义的替代文字。下图是项目本地资源：

## 列表与嵌套组合

无序列表项以 `-`、`+` 或 `*` 开头；有序列表项以数字和句点开头。子项目缩进至少两个空格。两种列表都可以包含强调、代码和链接：

- 父项目含有 **粗体文字** 和 `行内代码`。
  1. 编号子项目中有一个[指南链接](/quick-start/)。
  2. 另一个子项目含有 *斜体*。
- 第二个父项目。

GFM 任务列表会显示带有无障碍名称的静态状态符号，屏幕阅读器可以读出任务是否完成：

- [x] 已完成事项包含 **粗体文字**。
- [ ] 未完成事项包含 `代码`，并有嵌套子项：
  - [x] 该嵌套事项已经完成。

引用行以 `>` 开头。引用内容也可以嵌套其他块级语法，例如列表，以及行内强调：

> 引用句子中包含 **粗体文字** 和 `代码`。
>
> - 引用内部的列表项。
> - 第二个引用列表项中包含[链接](/project-introduction/)。

在每行前再增加一个 `>`，可以嵌套引用层级：

> 外层引用。
>
> > 内层引用包含 *斜体*。

这些示例把多种 Markdown 写法放在同一区域。生成的 HTML 会保留语义嵌套：引用中有列表、列表中有列表、列表项中有行内强调。

无序列表还可以用 `+` 开头，有序列表项也可以写作 `1)`：

+ 另一种无序列表项。
+ 第二个项目。

1) 使用右括号的有序项目。
2) 下一项。

## 表格与其他 GFM 语法

用竖线分隔单元格，用连字符分隔表头。冒号用于设置对齐方式。单元格也支持行内 Markdown：

| 语法 | 写法 | 渲染结果 |
| :--- | :---: | ---: |
| 强调 | `*文字*` | *文字* |
| 加重 | `**文字**` | **文字** |
| 代码 | `` `const x = 1` `` | `const x = 1` |

GFM 也会把 `www.example.com` 与 `https://example.com` 转换成链接，并支持上文的删除线和任务列表。窄屏幕上的表格可以横向滚动，列内容仍清晰可读。

## 安全行内 HTML 与支持范围

像 <kbd>Ctrl</kbd> 这样的简短语义 HTML 元素可以放进 Markdown。EdgePress 会清理生成的 HTML：保留安全文字、标题、列表、链接、图片、引用和表格；移除不安全属性和可执行脚本。下面这段原始脚本会在构建时被移除：

<script>alert('unsafe');</script>

视频请使用页面的「媒体与文字」元素；文章不允许嵌入框架或任意脚本。

本项目启用的文章语法范围是：CommonMark 的块级和行内语法，加上 GFM 表格、自动链接、任务列表与删除线。脚注、数学公式、Mermaid 图表、下划线语法和定义列表等扩展没有启用；除非添加受信任的渲染扩展，否则它们会作为普通文字显示。

## 在 EdgePress 中写文章

在 `content/posts/` 下为每篇文章建立目录，并放入 `en.md` 或 `zh-cn.md` 这样的语言文件。前置资料中的 `lang` 值必须与文件名匹配。添加标题、日期、网址别名、标签和可选摘要，再在前置资料之后编写 Markdown 正文。运行 `edgepress build` 生成文章；运行 `edgepress check` 则会构建网站，并输出无障碍、Agent 友好度、移动端截图与 Markdown 渲染报告。

本地文章搜索在浏览器中读取网站生成的 `search.json`，搜索文章标题和正文，不会把搜索词发送给第三方服务。
